# GigaChat E2E v1: причины 10 ошибочных verdict'ов

Источник истины для этого разбора — локальная запись FERMAT в
`selected.parquet`: `has_error`, `pert_a`, `pert_reasoning` и `orig_q`.
Фотография использована только как проверка того, что запись соответствует
изображению. Prompt остаётся `e2e/gigachat/v1`.

| ID | Тип основной причины | Что произошло |
|---|---|---|
| `img_110_pert_1.3` | Распознавание / нормализация | В FERMAT ошибочный промежуточный член `-1710 + 1700`; GigaChat его не сохранил и подменил цепочку значениями `1800`, затем `1710` и `cos(0)=0`. |
| `img_128_pert_1.5` | Математическая проверка | `\sqrt[3]{9000}` распознано верно, но модель не заметила, что это не равно `20`. |
| `img_136_pert_2.2` | Математическая логика / цель | Цепочка считана почти дословно, но модель не заметила замену задачи «разложить на множители» на поиск корней. |
| `img_157_pert_3.2` | Смешанная | Модель увидела умножение вместо сложения, но также ошибочно прочла второй исходный член как `2\sqrt2` вместо `\sqrt2`; после этого не отметила неверный переход. |
| `img_225_pert_2.4` | Распознавание / нормализация | Записанные `3^3=27` заменены на математически ожидаемые `3^2=9`. |
| `img_398_pert_4.4` | Распознавание / нормализация | Финальное ошибочное `dz/dx` заменено на `dy/dx`. |
| `img_462_pert_5.1` | Распознавание | Для определителя корректные `c=-1, d=2` переставлены в `c=2, d=-1`, поэтому модель сама получила ложный `-10`. |
| `img_480_pert_2.5` | Математическая проверка | Неверное умножение неравенства считано, но не распознано как ошибка: умножили на `2`, а затем получили результат как после умножения на `6`. |
| `img_494_pert_5.2` | Распознавание | Условие `2x-3=x+2` прочитано как `8x-3=x+2`; из-за этого корректное решение ошибочно отвергнуто. |
| `img_96_pert_2.1` | Распознавание / нормализация | Ошибочный знак во втором слагаемом и итог `-16/65` заменены на правильное вычисление `-56/65`. |

Итого: 6 ошибок распознавания/нормализации, 3 ошибки проверки уже корректно
распознанной записи и 1 смешанный случай. Следовательно, для GigaChat v1
главное ограничение — не только reasoning: модель часто «исправляет» запись
ученика при транскрипции и затем оценивает уже исправленный вариант.
