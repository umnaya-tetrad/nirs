# Assisted CAS: реализованный backlog

CAS проверяет написанную математику через SymPy. Модель предоставляет только
распознавание и структуру; её verdict, GT-метки и скрытые эталонные ответы не
участвуют в проверке. Неподдержанный случай остаётся `indeterminate`.

Обычный `analyze_contract` сохранён без изменений. Его parser, verifier и
structured verifier заморожены SHA-256 регрессией, а результаты ordinary на
всех 20 dev-примерах сравниваются с исходным снимком.

## Требования cas_task

| Требование | Реализация | Граница поддержки |
|---|---|---|
| Ответы и множества | `answers.py`, `exact_math.py`: интервалы, объединения, конечные списки, `±`, целочисленные аффинные семейства; raw LaTeX и причина отказа | Требуется полный разбор. Независимые компоненты передаются отдельно в `parse_answer_parts`; неоднозначная смесь переменных не объединяется |
| Граф шагов | `graph_verifier.py`: `role`, `derives_from`, `branch`, `uses_givens`; отдельные ветви, определения, подстановки, цепочки и ведущий `=` | Все узлы и рёбра должны быть доказаны для полного покрытия. Нет ссылок на будущие шаги, циклов, неизвестных givens или смешивания соседних окружений |
| Тригонометрия | Полные множества для многочленов степени 1–4 от одной sin/cos с линейным аргументом; точные сведения двойного угла/Пифагора; периодические классы, `±`, отбор на конечном отрезке | Неаффинный аргумент, свободные параметры и неразрешённые смешанные функции остаются unsupported. Точные преобразования проверяет граф; произвольный тригонометрический решатель не добавлен |
| Неравенства и ОДЗ | Линейные/квадратные и рациональные множества; исключённые знаменатели; положительная замена `t=a^x`; совместимые показательные основания; логарифмы с общим точным масштабом | Неопределённое основание, свободный параметр, нелинейная комбинация логарифмов или неразрешённое множество дают отказ. Границы не округляются |
| Вычислительные условия | `environment.py`: точные числовые givens и доказанные определения из предков ответа; корни, степени, факториалы; sin/cos по явным интервалам четвертей | Текст «second quadrant» не является математическим ограничением. Для факториала нужен целый аргумент от 0 до 100 |
| Первая ошибка | Самый ранний доказанный неверный узел по порядку чтения; контекст финала хранится отдельно | Более ранний неподдержанный шаг, в том числе в другой ветви, блокирует утверждение о первой ошибке |

Для новых классов есть positive, negative и unsupported tests в
`test_assisted_exact_math.py` и `test_assisted_graph.py`. Отдельно проверены
метрики и неизменность ordinary. Правила не зависят от ID примера.

## Как происходит проверка

1. `compile_task_spec` проецирует только разрешённые математические поля.
   Сериализованное представление хранит исходное условие и ошибки разбора.
2. Ordinary CAS создаёт независимое local evidence, как прежде.
3. Граф проверяет внутренние равенства и переходы от перечисленных предков.
   Определение даёт локальное окружение только своим потомкам. Полиномиальная
   или положительная показательная замена проверяется подстановкой дерева;
   новое значение уже существующей переменной проверяется по исходному условию.
   Неподдержанное определение вспомогательного уравнения не считается ошибкой
   только из-за отличия его множества решений от исходного. Ветвление
   доказывает включение отдельной ветви, а сборка ответа — полноту объединения.
4. Context rule строит точный ответ по видимому математическому условию и
   сравнивает его с записанным ответом. Для функций отдельно сравниваются
   значение и область определения всех четырёх различных операций.
5. Компоновщик сохраняет доказательства и выбирает канонический verdict.

Выход содержит:

- `problem.local_evidence` — прежнюю линейную проверку;
- `problem.graph_check` — статусы каждого узла и ребра;
- `problem.context_check` — статус, правило, причину и шаг проверки ответа;
- `problem.verified_solution_covered` — разобраны и проверены все узлы и рёбра;
- `problem.task_verified_solution_covered` — также сработала проверка условия;
- `problem.fallback_reasons` — причины отказа.

`INVALID` в context evidence при неизвестных предках не превращается в
вымышленный `first_error_step`. Canonical verdict тогда `indeterminate`,
первая ошибка `null`, а доказательство неверного финала остаётся в `problem`.
Верный финал также не покрывает неподдержанные шаги.

Недоступное context rule не отменяет доказанный ordinary local результат
для одной линейной цепочки. Перенос результата линейной проверки на независимые
ветви допускается только после проверки графа. Неуверенное/приблизительное OCR,
отсутствие exactness и некорректная структура графа дают отказ.

## Форматы и точность

```python
from nirs_cas.answers import parse_answer, parse_answer_parts

answer = parse_answer(r"x\in(-\infty;1]\cup(2;+\infty)")
print(answer.to_dict())  # raw_latex, status, set, reason
parts = parse_answer_parts([r"x=\pm1", r"y\in[0;2]"])
```

Для семейства обязательно явное `k\in\mathbb{Z}`. При пересечении
`x=πk` с `[100π;102π]` вычисляются точные нижняя и верхняя границы k,
а не перебирается заранее заданное окно. Открытые концы учитываются.
Ограничение размера результата — 10000 точек; выход за него означает отказ.

Входные строки разбираются ограниченной грамматикой, без `eval` и без
`sympify` модельного текста. Assisted parser расширяет обычную грамматику
отдельным классом. Десятичные числа остаются рациональными: `1.5` не
превращается в `15`; отрицательные подстановки выполняются на дереве выражения.
Внешние степени функций не смешиваются со степенью аргумента.

Удаляется только начальная презентационная метка вроде `\text{Ответ:}`.
Произвольные пояснения, условия и инструкции из `\text{...}` не используются
как факты. Неоднозначные массивы, дифференциальная запись, OCR-разрывы и
неразрешённые ограничения не исправляются автоматически.

Ordinary worker и assisted graph/context worker имеют отдельный лимит
10 секунд по умолчанию. Timeout или авария процесса превращаются в
структурированный отказ. `timeout=None` предназначен для доверенных unit tests.

## Воспроизведение

```sh
python -m pytest -q --basetemp ../.cas-work/pytest-check
python -m nirs_cas assisted-compare \
  --ordinary dataset/artifacts/gemini_ordinary_fermat_dev_20.json \
  --assisted dataset/artifacts/gemini_assisted_fermat_dev_20.json \
  --gt dataset/test_gt.json --output reports/local/assisted_dev20
python -m nirs_cas assisted-mixed-coverage \
  --bundle dataset/artifacts/gemini_assisted_mixed_20.json \
  --output reports/local/assisted_mixed20
```

Итоговые воспроизводимые отчёты находятся в
`reports/assisted_cas/backlog/dev20` и `reports/assisted_cas/backlog/mixed20`.
JSON содержит SHA-256 входов, результаты по случаям, покрытие классов и причины
отказа. Замороженные распознавания и prompts не изменены, VLM не запускался.

Verified solution coverage, доля вынесенных verdict и task-aware coverage
считаются раздельно. Ошибочный переход может быть локализован в частично
проверенном решении, поэтому incorrect не равен полному coverage.
First-error accuracy считается на GT incorrect; отказ не засчитывается как
успех. Сравнение ID строгое и зависит от совпадения сегментации OCR и GT.

Первый backlog-отчёт использовал dev-20 и инженерный mixed-20 без GT-оценки;
final-80 на том этапе не запускался. Следующий эксперимент с exact written CAS
и расширенной тригонометрией использует все 100 GT и сохранённый OCR:
[docs/cas_improvement.md](cas_improvement.md). Его результаты exploratory,
их нельзя представлять как независимую итоговую оценку.
