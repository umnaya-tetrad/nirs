# Эксперимент с точной проверкой написанных шагов

Доработан CAS на SymPy, а не нейросеть. Gemini/GigaChat, их prompts и сохранённые
распознавания не менялись. Новых запросов к моделям нет.

## Вход и режимы

`analyze_contract` и `oracle --mode ordinary` сохраняют прежнюю реализацию.
Новый `analyze_exact_contract` / `oracle --mode exact` использует
`written_exact.py`. В обоих режимах адаптер передаёт проверяющему исключительно
`steps[].latex` в порядке чтения. ID используются для обратного отображения
результата. `kind`, `derives_from`, GT verdict, findings, correction_latex,
transformation/rule_hint не определяют результат.

GT-100 состоит из `test_gt.json` (20) и `final_gt.json` (80). В этих контрактах
нет исходного условия задачи. Проверяется написанная математика относительно
начальной предпосылки: это не полная оценка соответствия исходной задаче.
Все 100 уже использованы для исследовательской разработки; новая независимая
выборка потребуется для итоговой оценки качества.

## Изменения

- Пояснение «вычитаем x из обеих частей» удаляется целиком, чтобы x из комментария
  не превращался в отдельное выражение. Поддержаны ограниченные презентационные
  метки, перечисления и вертикальная запись вычитания. Произвольные пояснения,
  единицы измерения и условия в тексте остаются unsupported.
- Равенства внутри цепочки проверяются отдельно. Ошибка в читаемом хвосте
  сохраняется даже при неизвестном начале строки.
- Одиночная предпосылка или итоговое выражение без проверяемого преобразования
  не засчитывается в полное покрытие. Вертикальное вычитание требует доказанного
  тождества и не принимается за исходное уравнение.
- Интервалы, `±` и неравенства сравниваются как точные множества решений.
  Явное `x≠0` сохраняет ОДЗ, а сокращение x/x без ограничения её изменяет.
- Пропущенная точка подстановки не восстанавливается по числу в ответе.
  Точное числовое определение переносится только после проверенного шага.
  Последующий ответ не должен противоречить доказанному значению переменной.
- В assisted-only парсере поддержаны отрицательные показатели без фигурных
  скобок; `i` обрабатывается как мнимая единица, как и в обычном парсере.
  Дифференциалы не читаются как произведения букв; без calculus verifier — отказ.
- Assisted trig rules расширены до многочлена степени 1–4 от одной sin/cos с
  точным линейным аргументом. Тождества двойного угла и Пифагора используются,
  если сводят уравнение к этому классу. Все ветви корней строятся полностью,
  отбор на конечном отрезке остаётся точным. Неаффинный аргумент, свободные
  параметры и неразрешённые смешанные функции остаются unsupported.

Модельные строки не передаются в `eval`/`sympify`. Набор числовых подстановок
никогда не доказывает тождество: допускается только точный контрпример для
опровержения. Worker имеет ограничение времени; отказ/таймаут не исключается
из знаменателя метрик.

## Ошибка и первая ошибка

Канонический `incorrect` требует установленной первой ошибки. Если ранний шаг
не проверен, `first_error_step` остаётся null и общий verdict — indeterminate.
При этом `problem.known_error_step_ids` содержит шаги с доказанной ошибкой,
а `problem.checks` — применённые правила и причины отказов. Потребитель может
подсветить такую ошибку, не называя её первой. Первая ошибка сравнивается по
исходным step_id; разбиение строк не подгоняется под GT.

## Воспроизведение

```sh
python -m nirs_cas oracle dataset/test_gt.json dataset/final_gt.json \
  --mode ordinary --output reports/local/gt_improvement/before
python -m nirs_cas oracle dataset/test_gt.json dataset/final_gt.json \
  --mode exact --output reports/local/gt_improvement/after
python -m nirs_cas oracle dataset/artifacts/gemini_ordinary_fermat_dev_20.json \
  --mode exact --output reports/local/gt_improvement/ocr
python -m nirs_cas improvement-report \
  --before reports/local/gt_improvement/before/report.json \
  --after reports/local/gt_improvement/after/report.json \
  --ocr reports/local/gt_improvement/ocr/report.json \
  --gt dataset/test_gt.json dataset/final_gt.json \
  --output reports/local/gt_improvement/comparison
python -m pytest -q
```

Проверенные результаты и все расхождения: [reports/cas_improvement](../reports/cas_improvement/README.md).
Новый режим остаётся экспериментальным: рост покрытия не означает улучшения
всех метрик. Отдельно проверяется обычный baseline (неизменные исходники и
замороженные результаты dev-20), а также assisted dev-20/mixed-20.
