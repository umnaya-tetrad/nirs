# Протокол предварительной проверки

Используемый CAS — SymPy. Объём работы: parser/normalizer и проверка жизнеспособности
на 20 примерах. Выборки FERMAT ещё нет, поэтому выполнены код и предварительная проверка.
Остальные исследовательские задачи не считаются завершёнными этим прототипом.

## Данные и критерий

`data/synthetic_20.json` содержит 20 **авторских синтетических** примеров, а не FERMAT.
Есть корректные и ошибочные переходы, потери корней/области определения и три заведомо
неподдерживаемых конструкции. Набор проверяет реализацию, не оценивает качество на данных
исследования. Высокая точность на нём не доказывает гипотезы H1–H3.

Для реального пилота нужна заранее зафиксированная выборка из **20 dev-примеров FERMAT**.
Порог: 14 из 20 (70%) полностью разобранных и проверенных решений. Неподдерживаемые,
таймауты и ошибки исполнения остаются в знаменателе. Не заменять неудобные примеры после
получения результата. Не использовать final test для адаптации парсера. Dev-разметка
хранится в `dataset/test_gt.json`, а разметка final-кейсов — в `dataset/final_gt.json`.
Исходные изображения и parquet с полями FERMAT в Git не добавляются.

Доступ к FERMAT требует авторизации и принятия условий доступа:
[официальная карточка набора](https://huggingface.co/datasets/ai4bharat/FERMAT).
Данные не скачивались, условия от имени пользователя не принимались.

## Формат входа

JSON с `kind` (`synthetic` или `fermat_dev`), `name` и массивом `examples` ровно из 20 объектов.
Каждый объект имеет уникальный `id` и не менее двух `steps`, каждый с непустым `latex`.
Для `fermat_dev` обязательны `source_id` исходной записи и `split: "dev"`.
Скрипт проверяет наличие метаданных, но не может подтвердить их достоверность.

```json
{
  "id": "fermat-dev-001",
  "source_id": "исходный-ID-из-FERMAT",
  "split": "dev",
  "steps": [{"latex": "2x+3=7"}, {"latex": "x=2"}],
  "has_error": false,
  "first_error_step": null
}
```

`has_error` и `first_error_step` — необязательная пара меток для сверки, а не вход
проверяющего алгоритма. Индексы **с 1**, ошибка перехода относится к следующему шагу.
Для ошибочного решения индекс обязателен. При интеграции согласовать конвенцию
с общим JSON проекта; здесь не навязывается схема VLM-адаптерам.

GT нельзя получать простой заменой `pert_a` на список строк без проверки: в FERMAT
могут быть текст, несколько выражений, условия и системы. Сегментация и сохранение
исходной предпосылки должны быть проверены человеком; неподдерживаемую математику
нельзя удалять ради повышения coverage. Локальные данные хранить в `data/private/`.

## Семантика ограниченного verifier

- Для уравнений сравниваются **множества действительных решений**, не только разности
  левой и правой части. Поэтому `2x=4 → x=2` корректно, `x²=4 → x=2` теряет корень.
- Для выражений нужны одинаковые значения и область определения; `x/x → 1` некорректно
  без явного сохранения ограничения `x != 0`.
- Первое символьное равенство — доверенная предпосылка. Проверки относительно `orig_q`
  и полноты ответа здесь нет. Ложное числовое равенство обнаруживается и на первом шаге.
- Многопеременные полиномиальные тождества поддержаны. Для многопеременных уравнений
  доказываются тождественность или умножение на ненулевую константу; прочее — `UNSUPPORTED`.
- Системы, неравенства, разбор случаев, переходы выражение↔уравнение, условные преобразования
  и неразрешённые символьные результаты — `UNSUPPORTED`. Это ограничение прототипа,
  а не ошибочный verdict ученику. Некоторые корректные преобразования корней дают отказ.
- Если ранее был неизвестный шаг, обнаруженная позднее ошибка не считается доказанным
  **первым** ошибочным шагом. `first_error_step` в таком случае остаётся `null`.

Полная coverage требует поддержки всех шагов/переходов, даже после обнаруженной ошибки.
`PARSE_FAILED` — статус разбора; итоговый статус проверки при этом `UNSUPPORTED`.
Таймаут даёт `NOT_MEASURED` для разбора: нельзя выдумывать результат незавершённого вычисления.

## Воспроизводимость

Команда из README сохраняет JSON со всеми переходами и причинами отказа, CSV и Markdown.
JSON содержит SHA-256 входного файла, версии Python/SymPy, время запуска, время вычисления
и полное время процесса. Каждый пример запускается в отдельном процессе с таймаутом
10 секунд (включая запуск процесса). Чистая latency не включает старт Python.

Coverage и parse rate считаются по всем 20 примерам; accuracy — только по поддержанным
примерам с метками, с отдельным знаменателем. У синтетического набора итог всегда
`PRELIMINARY_ONLY`, даже при превышении порога. `GO`/`NO-GO` выводится только для набора,
помеченного `fermat_dev`; GO означает достаточное покрытие, а не доказанную точность.

Прямой Python API не ограничивает время выполнения. Для внешних данных используйте
процессную оболочку CLI/benchmark; лимиты грамматики не заменяют изоляцию ресурсов
в будущем публичном сервисе. Для deployment потребуется отдельная инженерная задача.
