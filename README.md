# NIRS — VLM, GT и CAS

Экспериментальная система проверяет рукописные школьные решения по математике. Канонические JSON-схемы находятся в `data_contracts/`:

- `MathCoreInput 2.0` — дословная транскрипция VLM, передаваемая математическому ядру;
- `SolutionAnalysis` — единый результат E2E-VLM, GT и ветки VLM → CAS.

Поток работы: VLM либо сразу выдаёт `SolutionAnalysis` (режим `e2e`), либо сначала
транскрибирует изображение в `MathCoreInput` (режим `extraction`). Во втором режиме
CAS получает только канонический JSON и возвращает `SolutionAnalysis`. Он не должен
выдавать ложный вердикт для неподдерживаемой математики: в таких случаях результат —
`indeterminate`.

## Состав

- `nirs_llm/` — Gemini и GigaChat в режимах `e2e` и `extraction`.
- `nirs_cas/` — ограниченный LaTeX → SymPy verifier.
- `dataset/test_gt.json` и `dataset/test_gt_images/` — 20 размеченных dev-кейсов.
- `dataset/final_gt.json` — 80 размеченных final-кейсов. Текущая доработка CAS использует все 100 примеров, поэтому её результат — exploratory, а не независимая финальная оценка.
- `dataset_scripts/selected.json` — manifest 100 уникальных FERMAT-ID. Сам `selected.parquet` с изображениями хранится вне Git.

## Локальные фотографии FERMAT

Фотографии FERMAT не версионируются из-за объёма. Получите архив с выбранными
изображениями и распакуйте его в любую локальную папку, исключённую из Git; для
удобства можно использовать `data/images/` (она игнорируется по умолчанию).

У изображения должно быть имя `<FERMAT_ID>.png`: ID совпадает с полем `id` в GT и
с записью из `dataset_scripts/selected.json`. При VLM-прогоне передавайте путь к
нужному изображению явно; код не зависит от абсолютного пути или от одной жёстко
заданной папки.

Изображения нужны для VLM-прогонов и ручной сверки, но не для тестов контрактов и
CAS. Разделение dev-20/final-80 сохранено. После настройки CAS на всех 100 для
независимой оценки потребуется новая выборка. GT-метки не передаются проверяющему.

## Установка и тесты

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
pip install -e '.[test]'
pytest -q
```

Для VLM-прогонов скопируйте `.env.example` в `.env` и добавьте API-ключи. Сначала запускайте один кейс с `--fail-fast`; batch-артефакты пишутся в игнорируемый `outputs/`.

## Версии prompts

Промпты — версионируемые исследовательские артефакты в `prompts/<provider>/<mode>/vN/`.
Существующую версию не редактируют: для изменения добавляют следующий каталог `vN`.
Выбрать её при запуске можно так:

```sh
python -m nirs_llm.run --provider gemini --mode e2e --prompt-version v2 \
  --manifest dataset/manifests/fermat_dev_20.json
```

Gemini выполняет до двух запросов параллельно по умолчанию; число можно
изменить через `--workers N`. GigaChat всегда запускается в один поток: его API
не допускает параллельный batch-run.

Для временных сетевых сбоев, HTTP 408/429 и ответов 5xx раннер автоматически
делает до трёх попыток с короткой экспоненциальной паузой. Настроить число попыток
можно через `--max-attempts N`; ошибки JSON и контракта не повторяются.

Каждый новый output JSON сохраняет provider, mode, версию, оба фактически
применённых текста и их SHA-256. Для повторного запуска только фиксированного
подмножества передайте `--case-ids-file path/to/ids.json`; формат файла описан в
`prompts/README.md`.

## Extraction-контракт 2.0

В режиме `extraction` модель — только распознаватель. Она возвращает упорядоченный
список дословных LaTeX-строк решения и `ambiguous_step_ids`, если строка прочитана
неуверенно. Она не возвращает тип задачи, условие, цель, relation уравнения,
нормализованный LaTeX или текстовые пояснения. Оркестратор сам добавляет линейные
`step_id`, `kind` и `derives_from`, а CAS работает исключительно с этим контрактом.

Текущие prompts: Gemini extraction `v2`, GigaChat extraction `v3`. Ранее сохранённые
extraction-артефакты версии 1.0 с полем `problem` — исторические и не валидируются
как `MathCoreInput 2.0`; E2E-артефакты и GT `SolutionAnalysis 1.0` от этого не меняются.

## Проверка CAS на GT

Файл `dataset/final_gt.json` содержит 80 решений (6402 строки),
`dataset/test_gt.json` — ещё 20. Адаптер `nirs_cas/adapter.py`, функция
`extract_step_latex`, извлекает только `steps[].latex`, сохраняя порядок.
Он принимает один канонический объект или runner-обёртку `{"contract": ...}`.
Массив решений читает `nirs_cas/oracle.py`; GT-вердикты и первая ошибка
используются только для сравнения после CAS-проверки.

```sh
python -m nirs_cas oracle dataset/test_gt.json dataset/final_gt.json --output reports/local/gt_100
```

Результат: `report.json`, `results.csv`, `report.md` и канонические
`SolutionAnalysis` в `predictions/`. Каждый пример проверяется в отдельном
процессе с таймаутом; по умолчанию одновременно работают четыре процесса.
Можно передать только один файл или JSON с сохранёнными распознанными шагами.

Docker использует тот же GT-вход:

```sh
docker compose run --build --rm cas
docker compose --profile test run --build --rm tests
```

## Граница CAS

CAS проверяет арифметику, алгебраические переходы с областью определения,
цепочки равенств, продолжения с `=`, определители, явные матрицы, факториалы,
тригонометрические выражения и простые неравенства. Полная поддержка интегралов,
производных, систем, векторной и символьной матричной алгебры пока отсутствует.
Условия задачи, размерности, пропущенные подстановки и выбор ветви не выводятся
из GT-подсказок: неподтверждённые проверки остаются `UNSUPPORTED`.

`covered` требует проверки всех записанных шагов. Независимое неверное равенство
может установить `has_error=true` и при неполном покрытии. Если более ранний шаг
не проверен, `first_error_step` остаётся пустым и канонический вердикт —
`indeterminate`. Начальная символьная предпосылка принимается как данная;
правильность относительно исходной задачи и полнота ответа не устанавливаются.
Доказательство тождества строго символьное. Для опровержения также допустим
точный контрпример в области определения, без численных допусков.

Метрики на всех примерах учитывают отказы как неуспех. Точность на покрытых
публикуется отдельно. Исторический synthetic-20 отчёт не является результатом
на FERMAT. Текущий GT-прогон: `reports/cas_gt_100/`.
